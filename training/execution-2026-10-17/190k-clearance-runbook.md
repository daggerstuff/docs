# 190k corpus: operational clearance runbook

Candidate: 190,139 rows, SHA-256 `4f0fd4c5fcfdffeb5434057ff4e122356256f9775540a3b41c1421a75e507663`.
Queue: [`190k-source-clearance-worklist.csv`](190k-source-clearance-worklist.csv) — 475 metadata source labels, grouped counts, default exclusion, reviewer fields. It reconciles to 190,139 rows. The row-reference ledger is `source-decision-ledger.jsonl` (836 groups, all candidate rows).

## Do this in order

1. Freeze the original candidate. The working output is always a new dataset/hash.
2. Exclude immediately: every label whose acquisition label explicitly names torrent/Bookflare sources (1,060 rows); every Reddit-derived row (151,279) unless content-rightsholder permission is produced; every unmapped label (12,716) until curator can identify it. I joined these against the exact ledger row numbers: the first-pass quarantine is **163,995 unique rows** because the 1,060 piracy-labeled rows are already inside the unmatched set. This leaves **26,144 rows** in mapped, non-Reddit source groups for source-by-source decisions. The original corpus remains unchanged; these are release-build exclusions.
3. Work the remaining mapped non-Reddit groups in batches. These are source permissions, not conversation reviews. Apply the decision to every rowref of that exact source/version using the ledger and the CSV.
4. For any batch with missing evidence, set `EXCLUDE`. For a batch with evidence, fill all reviewer/evidence/provider fields. The rights reviewer must determine that the grant covers fine-tuning and intended downstream use. Chad can record privacy controls and whether existing consent/authorization covers processing; he cannot manufacture absent participant consent or source rights.
5. Curator emits a new rowref manifest for approved rows, then builds a new JSONL by candidate row number, validates each emitted row hash against the ledger, computes the new corpus hash, and runs automated schema, duplicate, split-leakage, identifier, and loss-mask checks. W&B upload is allowed only for a release manifest whose approved rowrefs and evidence hashes match that new corpus hash.

## Permission request text

Send to each rightsholder/maintainer (no examples attached):

> We have [N] records attributed to [dataset, exact version/hash]. Do you control the rights needed to authorize Pixelated Empathy to use these records for supervised fine-tuning and evaluation of our models, including our intended commercial product? Processing would occur in [W&B account/product] and any additional providers listed in the attached scope. Please confirm whether the grant covers derived model/adapters, retention/export to our own infrastructure, and state attribution, deletion, or downstream limits. If you cannot grant this, please identify the rights holder or tell us to exclude the source. Please also identify any source components or contributors that are outside the grant.

Save the reply as an access-controlled evidence file, calculate its SHA-256, and put the file path/hash, rights decision, scope, reviewer, and date in the CSV. Chad separately records the privacy/consent determination and exclusions against the candidate hash and source version. A website's license is saved as a dated copy with URL/hash; it counts only if its text actually covers the planned use and the licensor can grant those rights.
