# Ordinary-support repair evidence

This is an opt-in, unpromoted middleware experiment. The original v18 implementation, source rows, splits, adapter weights, booking path and two raw task flags remain unchanged. All new requests and author-labeled controls are adaptive synthetic development data. The final run and review counts are in `repair-results.json`; consult that file rather than assuming the last attempt passed.

The initial fresh baseline withheld both action-only responses because repeated drafts omitted manageable scaling. Subsequent real runs exposed false rejection of supplied reframes, invented action requirements for general support, repeated failed corrections, and future-availability wording. No failed response or judge result was relabeled or removed.

The repair distinguishes supplied alternative interpretations from assigned physical, breathing, writing and household exercises. A general request for support can be fulfilled by validation; it does not automatically require advice. The final nonclinical action-scope calibration includes all 17 legacy anchors and 20 added contrasts, including real failed reframe traces. All 37 labels matched. This is a prospective project quality definition, not a clinical standard.

The acknowledgment reviewer uses a compact two-field `met`/`correction` schema. Calibration v11 matched all 24 frozen positive/negative labels, with all 28 responses strict-valid, including four original-response diagnostics that have no expected labels. It separately honors quiet-company/no-reflection/action-only requests. This does not change the original v18 rubric or flags. Prior judge versions and failures remain under acknowledgment-v1 through v10. Versions v7/v8 were rejected during setup before any provider call; versions v3/v6/v9 had incomplete outputs, and other versions had semantic disagreements with the fixed labels.

The ordinary-draft gate now checks acknowledgment after actual task completion and adjustment review. Revisions include the rejected assistant draft and an explicit correction turn. They remove the legacy generic breathing example, which was pulling reframe repairs away from their actual task. Only ordinary revisions use temperature 1.0; first-draft and tool decoding remain unchanged. The actual decoding is retained in provider ledgers. After two rejected drafts, the final variant can use Gemma as a disclosed fallback, within the existing four-draft bound. This is mixed middleware, not evidence that Nemotron adapter weights were repaired.

The last identified repair-loop defect was an ambiguous warning to remove availability promises. Both models repeatedly kept “not going anywhere.” The new correction identifies the exact phrase already rejected by the existing filter and asks for present-moment wording, so the generator can identify the actual failure. The filter remains active.

Gemma participates in routing, runtime review, fallback generation and final review. Those judgments are correlated; blinding does not make them independent-model evidence. Final quality review does not assess clinical safety. Paige Taylor's qualification and independence are verified by the user's October 22 confirmation. Her completed assessment remains outstanding. No deployment or deployment recommendation is authorized.

Research used to select and constrain the fixes:

- [vLLM issue 40080](https://github.com/vllm-project/vllm/issues/40080) reports Gemma structured-output repetition, including whitespace-padding loops. Our v3 traces show the same observable symptom, but we cannot infer the hosted provider's serving version or diagnose its backend from that similarity. [The official structured-output configuration](https://docs.vllm.ai/en/latest/api/vllm/config/structured_outputs/) documents compact-whitespace controls as engine configuration; we did not assume access to those server flags. A bounded 12-call comparison found complete output in 6/6 schema-constrained and 6/6 plain-JSON requests after an explicit compact-output instruction. Strict client validation remained enabled.
- [Google's Gemma thinking guide](https://ai.google.dev/gemma/docs/capabilities/thinking) documents the thinking switch. Thinking improved the observed recognition distinction but still exhausted the token limit on a calibration case; it was not adopted as a cure. [Google's model card](https://ai.google.dev/gemma/docs/core/model_card_4) recommends temperature 1.0. A separately disclosed sampled diagnostic still had a truncation, so raising temperature was not treated as a sufficient structured-judge fix.
- [NVIDIA's Nemotron 3.5 Lightning model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16) recommends temperature 1.0 and top-p 0.95. We tested temperature 1.0 only for ordinary revisions to break observed deterministic repeats. We did not claim to have tested the full recommended sampling configuration, or relax the paired harness's temperature-zero contract.
- [NHS reframing guidance](https://www.nhs.uk/every-mind-matters/mental-wellbeing-tips/self-help-cbt-techniques/reframing-unhelpful-thoughts/) describes exploring alternative interpretations. It supports the conceptual distinction being investigated; it does not validate our classifier, acceptance criteria or generated responses.
